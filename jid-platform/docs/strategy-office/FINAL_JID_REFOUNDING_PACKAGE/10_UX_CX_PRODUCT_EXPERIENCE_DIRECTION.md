# UX/CX and Product Experience Direction

## Experience thesis

JID should feel like a **living professional instrument**: calm, credible and responsive to a person's real next step. It should not feel like a static profile museum, decorative dashboard or generic AI SaaS shell.

## Emotional model

- **Clarity:** what is true, what is unknown and what happens next.
- **Agency:** the user chooses goals, disclosure and actions.
- **Momentum:** every step produces visible utility without gamified pressure.
- **Dignity:** rejection, uncertainty and missing history are handled respectfully.
- **Trust:** source, freshness, verification, consent and AI involvement are legible.

## Information architecture

### Individual

`Home → Career Record → Explore → Opportunities → Radar → Guidance → Messages → Settings/Privacy`

Home is a finite task briefing: next actions, relevant changes and purposeful reminders. It is not a general content feed.

### Employer

`Home → Opportunities → Candidates → Programs/Talent Pools → Communications → Organization Profile → Insights → Settings`

### University

`Home → Cohorts → Outcomes → Career Services → Employers/Programs → Reports → Institution Profile → Data & Governance`

Staff/internal navigation remains operational and permission-led.

## Home experience by actor

- Individual: one goal, next actions, fresh relevant opportunities, Radar changes and record/evidence prompts.
- Employer: open roles, candidates requiring action, communication deadlines, data-quality warnings and program status.
- University: cohort collection progress, coverage warnings, unresolved data issues and actions—not a grid of empty KPIs.

## Arabic-first behavior

- author Arabic information architecture and copy before English localization;
- short, direct Saudi Arabic product language without bureaucratic translation;
- Latin digits in both languages;
- logical CSS and meaningful RTL ordering, not mirrored decoration;
- search supports Arabic variants and bilingual occupation/company names;
- no Arabic letter-spacing;
- mixed Arabic/English names and codes use directional isolation;
- user testing includes Arabic-first participants, not translation review only.

## Visual direction

Preserve JID's olive structure, warm-neutral surfaces, restrained gold, custom logo assets and semantic tokens. Use real product artifacts and Saudi context only when sourced. Density should follow the task:

- narrative/progression for the Individual;
- tables, queues and stages for employer/internal operations;
- methodology, coverage and comparative tables for universities.

Cards are for real objects, not layout filler. Charts require a comparison question. A percentage without a source/denominator does not render.

## Signature interaction

The proposed signature artifact is the **Career Pathline**: a horizontally/vertically adaptive view connecting evidence already earned, current goal, required steps, active opportunities and outcomes. It is not a social timeline and does not duplicate facts; it points to canonical objects.

## Progressive disclosure

- start from goal and immediate utility;
- request only facts needed for the next useful output;
- show source/verification/visibility details on demand;
- place advanced configuration in context;
- never block basic value behind arbitrary “profile completion.”

## Honest states

- Empty: no data exists and a relevant action is available.
- Unknown: the platform lacks coverage or a response.
- Unavailable: a dependency/source is not operating.
- Forbidden: the viewer lacks permission.
- Error: a request failed and can be retried or reported.
- Stale: data exists but its freshness threshold expired.

Unknown and error never become zero. Every dynamic module disappears cleanly when irrelevant.

## Motion and notification

Motion may explain state change, provenance or progress; it cannot hide content or create urgency. Respect reduced motion. Notifications must be actionable, grouped, rate-controlled and purpose-based. No generic “come back” nudges.

## Accessibility

- semantic landmarks/headings;
- keyboard-complete workflows;
- visible focus and sufficient contrast;
- accessible drag/drop alternatives;
- transcript/caption and assessment accommodations;
- generous touch targets;
- no color-only status;
- readable finite tables on mobile using deliberate content reflow;
- Arabic and English screen-reader testing.

## Anti-slop gate

Reject: generic split hero, floating metric cards, pill saturation, decorative percentages, fake window mockups, unsupported logos, default feature grids, glass/gradient decoration, hover lift everywhere, dead controls and reused demo content. Distinction comes from product specificity, authored data relationships and one coherent signature artifact.

## Validation

Test four complete prototypes in Arabic first: Individual record-to-opportunity, employer opportunity-to-decision, university cohort-to-insight, and consent/revocation. Measure task completion, comprehension, correction, error recovery and perceived trust—not aesthetic preference alone.
